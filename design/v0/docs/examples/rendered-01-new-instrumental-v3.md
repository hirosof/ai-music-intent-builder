## 1. 依頼文（全文）

以下をそのままチャットAIに貼り付ける。

```
# 音楽生成AI用プロンプト作成依頼

## 1. 依頼の前提

- あなたの役割は、音楽生成AI「Suno v6（アドバンスドモード）」の入力欄に貼り付けるテキストを作ることです。
- あなた自身が音楽・音声・画像・動画を生成する機能を持っている場合でも、この依頼ではそれらを起動しないでください。求めているのはテキストのみです。
- 私に確認の質問はしないでください。情報が足りない箇所は §2 のルールに従って補完し、1回の回答で最後まで出力してください。判断に迷った点は、質問ではなく最後の「注意事項」に書いてください。
- 今回の対象は、新規生成の楽曲1曲です。
- 回答の説明文は日本語で書いてください。各欄に入れるテキスト自体の言語は §5 の表に従います。
- 今回はインストゥルメンタル（歌詞のない楽曲）です。歌詞は作らないでください。Suno では歌詞欄を空にすることがインストの条件であるため、歌詞欄は出力の対象外です。
- 歌詞欄に入れる構成タグ（[Verse] や [Chorus] など）も出力しないでください。曲の展開はスタイル欄の文章として表現してください。
- インストになるかどうかは歌詞欄を空にすることで決まります。歌が入ることを心配して、「スタイルを除外」欄に歌唱や歌詞に関する語を足す必要はありません。

## 2. 値の状態の読み方

§6 の要件表では、すべての項目に「状態」が付いています。意味は次のとおりです。

| 状態 | 意味 | あなたの扱い |
|---|---|---|
| 指定 | 私が値を決めた | その値に従う。§2-2 の範囲で言い換え・具体化してよい |
| お任せ | あなたが決めてよい | §2-1 に従って決める。決めた内容は補完一覧に書く |
| 既定値 | 既定値をそのまま使う（値は表に書いてある） | その値を前提にしてよい。補完一覧には書かない |
| ツール任せ | 生成時に Suno 側が決める（値は誰にもわからない） | その値を前提にした記述をしない。補完一覧には書かない |

### 2-1. 「お任せ」の決め方

- 「値」の列に、何から導くかの手がかりを書いています。手がかりに挙げた項目自体が「お任せ」の場合は、さらにその上位の手がかりをたどってください。
- 最終的な拠り所は「用途」です。用途も「お任せ」の場合は、「特定の用途を想定しない楽曲」として扱ってください。
- 「指定しないまま残す」と書かれている項目は、何も決めず、その要素に触れないまま出力してください。指定していない要素が勝手に増えることを避けるためです。

### 2-2. 具体化の許容度

「具体化」の列は次の分類です。

| 分類 | できること |
|---|---|
| 拡張可 | 指定を出発点に、それに合う要素を足してよい |
| 翻案可 | 指定を別の言葉に置き換えてよい。要素は足さない |
| 保持 | 指定をそのまま使う。言い換えも最小限にとどめる |

### 2-3. 具体化した内容を書く場所

ある項目を具体化した結果が別の軸の内容になる場合、その内容は本来の軸の記述として書いてください。

例: 「和風」（様式）から尺八と太鼓を導いた場合、尺八と太鼓は「音の構成」の内容として書きます。様式の記述を「和風（尺八と太鼓を含む）」のように膨らませないでください。同じ内容が複数箇所に現れると、文字数を無駄に使います。

## 3. 優先順位

矛盾が生じたときは、上にあるものを優先してください。優先順位はこの節だけで定義します。他の節に個別の優先ルールは書きません。

1. §4 の禁止事項
2. Suno の制約（欄の有無、文字数上限、§5-2 で確定している設定）
3. 私の指定（状態が「指定」のもの）
4. あなたの補完（状態が「お任せ」のもの）

「私の指定」の中で矛盾がある場合は、次のとおりに扱ってください。

- 自由記述（「その他・補足」）と構造化された項目が矛盾する場合は、自由記述を優先する
- 「使用する」と「使用しない」が矛盾する場合は、使用しない（除外）を優先する

矛盾を解決した場合は、「何と何が矛盾し、どちらを採ったか」を「注意事項」に書いてください。

## 4. 禁止事項

- 実在するアーティスト名・グループ名・曲名・既存の歌詞を使わないでください。理由は2つあります。ひとつは権利上の問題、もうひとつは Suno 側で生成を拒否される原因になることです。
- 参考にしたい対象がある場合は、名前を出さず、ジャンル・年代・楽器編成・演奏の質感・歌い方といった特徴に分解して表現してください。
- 私の入力に実在の固有名詞が含まれていた場合も、無視せずに特徴へ分解して使い、分解したことを「注意事項」に書いてください。
- 暴力・差別・性的な表現など、不適切な内容を含めないでください。

## 5. 対象ツールと出力欄

対象: Suno v6（アドバンスドモード）

### 5-1. 出力する欄

| 欄 | 上限 | 目標 | 言語 |
|---|---|---|---|
| スタイル | 1000文字 | 900文字以内 | 英語を基本とし、日本固有のジャンル名・様式名は日本語のままでよい |
| スタイルを除外 | 1000文字 | 900文字以内 | 英語を基本とし、日本固有のジャンル名・様式名は日本語のままでよい |

- 上限は Suno 側の制限です。目標は上限の9割で、余裕を持たせるための値です。
- 文字数を数えて申告する必要はありません。目標の長さに収まるように書いてください。文字数の確認は私の側で行います。

### 5-2. Suno 側で確定している設定（本文に書かないこと）

次の設定は Suno の UI で私が指定します。スタイル欄の文章の中で重ねて指定しないでください。

| 設定 | 値 |
|---|---|
| 長さ | 3:00 |
| バリエーション | 標準 |
| 奇抜さ | 50%（既定値） |
| スタイルの影響 | 50%（既定値） |
| Max モード | オフ |

これらの値は、曲の長さやループの尺度としても本文に書かないでください（例:「3分間のループ」のような書き方をしない）。

### 5-3. 書き方

- 重要な要素を先頭に置いてください。
- スタイル欄の要素の順序は、ジャンル・様式 → 声の扱い → テンポ（BPM） → 情緒・雰囲気 → 楽器編成 → 質感 を基本としてください。
- 複数のジャンルを組み合わせる場合は、主となるジャンルを先に書き、他を with や meets でつないでください。
- 楽器は役割を明示してください（主旋律を担う楽器、伴奏を担う楽器、リズムを担う楽器）。
- スタイル欄は「あるもの」を書く欄です。no / without / rather than などの否定表現を使わないでください。除外したい要素は「スタイルを除外」欄に書きます。
- 今回はインストです。声に関する指定がある場合でも、歌詞のある歌にならない表現を選んでください（例: 言葉のない合唱、ハミング）。
- バリエーション設定が「標準」のため、あなたが書いたスタイルは Suno 側で書き換えられます。あなたの記述は最終形ではなく、書き換えの元になる材料です。細部を書き込むより、曲の性格を決める核となる要素を短く、前方に置いてください。

## 6. 楽曲の要件

状態の意味は §2 を参照してください。「具体化」の列は §2-2 の分類です。

### A. 用途・文脈

| 用途 | 指定 | ゲームのボス戦BGM | 拡張可 |

| 想定する聴取環境 | 指定 | ループ再生する | 翻案可 |

### B. ジャンル・様式

| 項目 | 状態 | 値 | 具体化 |
|---|---|---|---|
| 主ジャンル | 指定 | オーケストラ | 翻案可 |
| 年代・時代感 | お任せ | お任せ — ジャンルから導く。導けない場合は指定しない | — |

| 項目 | 状態 | 使用する | 使用しない | 具体化 |
|---|---|---|---|---|

### C. 情緒・雰囲気

|---|---|---|---|

| 構成（セクションの並び） | お任せ | お任せ — 指定しないまま残す | — |

### 除外・補足

| 項目 | 状態 | 値 | 具体化 |
|---|---|---|---|

| その他・補足 | お任せ | お任せ — 指定しないまま残す | — |

「使用しない」の列に挙げた要素と、「除外したい要素」に書いた内容は、まとめて「スタイルを除外」欄に出力してください。スタイル欄の中に否定形（no ○○ など）で書かないでください。

「スタイルを除外」欄の書き方は次のとおりです。

- 除外したい要素をそのまま並べてください。No や without を付けないでください。この欄自体が除外を表すため、付けると二重否定になります。
- 「使用しない」と「除外したい要素」に挙がっているものは、すべて漏れなく書いてください。減らさないでください。
- 「使用しない」と「除外したい要素」に挙がっていない要素を足さないでください。関連する語への展開や具体化もしないでください（例:「ケルト」を「ケルト, ティンホイッスル, バウロン」に広げない）。§2-2 の「具体化」は「使用する」側にのみ適用されます。

## 7. 出力形式

### 7-1. 全体の構成

次の順で出力してください。

1. 案ごとの出力（3 案）
2. 補完一覧
3. 注意事項
4. 補足（必要な場合のみ）

各案の見出しには「案 N / 3」のように、何番目の案かと総数を明記してください。

上記以外の成果物（ファイルなど）は作らないでください。前置きや後書きも不要です。

### 7-2. 各案に含めるもの

案ごとに、次を順に書いてください。

- 基本プロンプト: スタイル欄に入れる短い版。曲の性格を決める核となる要素だけを書く（ジャンル、様式、情緒の中心、主要な楽器）。数語から30語程度。コードブロックで囲む
- 詳細プロンプト: スタイル欄に入れる完成版。テンポ、楽器編成、声の扱い、強弱の変化、残響やミックスまで含む。900文字以内。コードブロックで囲む
- 日本語訳
- この案の狙い: 1〜2文。他の案と何を変えたかを含める
- スタイルを除外: コードブロックで囲む

基本プロンプトと詳細プロンプトは、同じ要件から作られた2つの表現です。基本プロンプトは詳細プロンプトの核を抜き出したものであり、両者の内容が矛盾しないようにしてください。

### 7-3. 案ごとの差の付け方

- 状態が「指定」の項目は、どの案でも変えないでください。
- 「スタイルを除外」欄の内容は、どの案でも同じにしてください。
- 差を付けてよいのは、状態が「お任せ」の項目と、「指定」項目を具体化する範囲です。
- 今回の差の付け方: 差を付ける軸はあなたが選んでください

### 7-4. 訳

基本プロンプトと詳細プロンプトのそれぞれの直後に、日本語訳を付けてください。片方だけにしないでください。訳はコードブロックには入れず、通常の文章として書いてください。コピーの対象と区別するためです。

### 7-5. 補完一覧

- 状態が「お任せ」だった項目について、あなたが決めた内容を表で示してください。列は「項目」「決めた内容」「理由」です。理由は1行で簡潔に書いてください。
- 表には全案に共通する補完だけを載せてください。案ごとに内容が異なる項目は、表の「決めた内容」に「案ごとに異なる」とだけ書き、実際の内容は各案の「狙い」に書いてください。
- 状態が「指定」の項目を具体化した内容（例:「和風」から尺八を導いた）は、この表に含めないでください。
- 「指定しないまま残す」と書かれていた項目についても、そのまま残した旨を1行書いてください。

### 7-6. 注意事項

次に当てはまるものがあれば書いてください。なければこの節ごと省略してください。

- 矛盾を解決した箇所（何と何が矛盾し、どちらを採ったか）
- 実在の固有名詞を特徴に分解した箇所
- 私に確認したかったが、§1 の指示により質問せずに判断した箇所
```

## 9. Haiku 4.5 の扱い

3回を通して、逸脱は Haiku 4.5 に集中している。

| 回 | Haiku 4.5 の逸脱 |
|---|---|
| 1 | V-01（長さ混入）/ V-04（No 付き、項目追加）/ §7-4（訳の欠落） |

| 3 | V-16（脱落）/ V-18（前置き・後書き）/ H-03（存在しない設定への言及） |

重大度は下がっているが、**指示量を増やしても他の4モデルと同水準にはならない**。
依頼文は約 4,200 → 4,550 → 4,700 文字と増えてきたが、
これ以上 Haiku 4.5 のために書き足すのは割に合わない。

方針の候補:

1. **推奨モデルを示す** — ツールの UI や README で上位モデルの使用を推奨する
2. **何もしない** — 依頼文は上位モデルを前提とし、小型モデルでの結果は保証しない
3. **簡略版の依頼文を用意する** — 小型モデル向けに規則を削った版を別途作る

現時点の既定: **1**。依頼文を分岐させる（3）は保守対象が2倍になるため、
小型モデルを使う必然性が確認されるまでは採らない。
