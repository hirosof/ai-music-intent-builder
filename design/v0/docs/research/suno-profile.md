### 上限値の状態

| 状態 | 該当項目 |
|---|---|
| 確認済み | 歌詞 5,000 / スタイル 1,000 / スタイルを除外 1,000 / 曲名 80 |

### 長さの入力形式
- 秒数と M:SS 形式の**両方**を受け付ける
  - 「180」と入力 → 「3:00」と表示される
  - 「1:41」と入力 → 「1:41」のまま
- 表示は M:SS 形式に正規化される

### モードによる入力欄の差（実画面、2026-09-16）

| 欄 | アドバンスド | シンプル |
|---|---|---|
| 歌詞 | あり（専用欄） | **なし** |
| スタイル | あり（専用欄） | 単一のプロンプト欄のみ |
| スタイルを除外 | あり（「その他のオプション」内） | **なし** |
| 添付 | オーディオ / Voice / インスピレーション | オーディオ / Voice / 画像 |

アドバンスドの歌詞欄のプレースホルダは
「歌詞を書き始めるか、インスト用に空のままにしてください」。
→ **インスト化は歌詞欄を空にすることで担保されるという前提を、UI の文言が直接裏付けている**。
これは `decisions/request-text.md` の判断ポイント8（F-02: 除外欄に歌唱系の語を足さない）の根拠になる。

シンプルモードには除外欄も歌詞欄もないため、
本ツールの依頼文はそのままでは使えない（B-05x / B-06x が意味を持たず、
インスト指定の手段も不明）。シンプルモードは引き続き対象外とする。

## 3. リミックスモードの操作一覧

「ボーカルを編集」ドロップダウンから選択する操作は15種類。
テキスト指示の有無は説明文からの推測を含む。

| 区分 | 操作 | プラン | テキスト指示 | 本ツールでの扱い |
|---|---|---|---|---|
| REMIX | Cover（別のジャンルや感じでこの曲を作り直す） | — | あり | 将来の候補 |
| REMIX | Mashup（選んだ別の曲とブレンド） | — | 不明 | 将来の候補（優先度低） |
| REMIX | Sample（新しいトラックの中でオーディオの一部を使う） | — | あり | 将来の候補 |
| REMIX | インスピレーション（ゆるくインスパイアを — バイブだけ、細部なし） | Pro | あり | 将来の候補 |
| 編集 | 延長（この曲を止まったところから続ける） | — | あり | 将来の候補 |
| 編集 | トリミング | — | なし | **対象外** |
| 編集 | セクションを削除 | — | なし | **対象外** |
| 編集 | 逆再生 | — | なし | **対象外** |
| 編集 | 速度 | — | なし | **対象外** |
| 編集 | 楽器を編集（曲の楽器編成を追加または置き換える） | Pro | あり | 将来の候補 |
| 編集 | **ボーカルを編集**（曲のボーカルパフォーマンスを追加または置き換える） | Pro | あり | **派生生成の第一候補（L-01b）** |
| 編集 | セクションを置き換え（曲の一部を入れ替える） | Pro | あり | 将来の候補（R-04 の代替手段にもなり得る） |
| 編集 | フェードイン | Pro | なし | **対象外** |
| 編集 | フェードアウト | Pro | なし | **対象外** |
| 編集 | stem を追加（新しい stem を重ねる: drums, bass, lead など） | Premier | 不明 | 将来の候補 |

### リミックスモードへの導線

- ワークスペースから過去に作成した元曲をドラッグ＆ドロップ
- 「＋オーディオ」から過去に作成した曲を選択
- （複数の導線がある）

本ツールは Suno を操作しないため、導線の違いは仕様に影響しない。

### リミックス移行時のスタイルの扱い

- 元曲のスタイルが最初からスタイル欄に入っている
- スタイル等が入力済みの状態で移行しようとすると、
  **「元曲のスタイルを反映」か「現在の設定を保持」かを選べる**
- → 派生生成の依頼文は、どちらを選んだ前提なのかを明示する必要がある

## 4. アカウントに紐づく要素

以下は**ユーザーのアカウントに保存され、中身をチャットAI が知る方法がない**。

| 要素 | 内容 |
|---|---|
| 作詞家 | サンプルの歌詞から作る歌詞ペルソナ。「Suno の書き方を導く歌詞ペルソナを保存します」「個性を表す歌詞から作詞家を作成」 |
| Voice | ユーザーの声を複製（v5.5 で追加） |
| Custom Model | アップロードした曲から作るモデル（v6 のモデル選択に表示。未確認） |
| パーソナライズ | 利用履歴から学習（マイ・テイスト） |

### 扱いの方針

- 依頼文には「使う／使わない」だけを前提として書く。中身はチャットAI に判断させない
- 使う場合はチャットAI の指定を控えめにさせる
  - 例: 作詞家を使うなら、作詞AI への指示文では語り口や語彙を細かく指定せず、
    テーマや構成の指示にとどめる（作詞家の作風と指示の衝突を避ける）
- 任意で、ユーザーが中身を短く説明できる欄を設ける（例:「素朴な言葉づかいの作詞家」）

これは R-13（UI 設定と本文の二重指定）と同種の問題。
アカウントに紐づく要素も「指定の経路」の1つと見なせる。

## 5. 実例と観察

### 5-1. バリエーションによるスタイルの書き換え

入力スタイル: `和風戦闘BGM , Choir` / バリエーション: 標準

生成曲1のスタイル:
```
和風戦闘BGM, midtempo rising drama shōtaiko and taiko with brass koto strings,
layered wordless choir, restrained minor-key opening through dramatic dynamic swells,
cinematic studio reverb and powerful climactic accents
```

生成曲2のスタイル:
```
和風戦闘BGM, 広大な礼拝的リバーブ, 尺八と太鼓を基調とする重弦アンサンブル,
無声合唱による重層的防御感, 中速で急迫する進行, 荘厳なスタジオミックス
```

観察:

| 観察 | 内容 |
|---|---|
| 先頭の要素 | `和風戦闘BGM` は2曲とも原文のまま先頭に残った（→「重要な要素を先頭に」の根拠。ただし1入力2テイクのみの仮説） |
| 2番目の要素 | `Choir` は原文のままではなく書き換えられて取り込まれた |
| 書き換え後の言語 | 生成曲1はほぼ英語、生成曲2はほぼ日本語。**同じ入力でもテイクによって言語が変わる** |
| 共通の骨格 | 2曲とも テンポ / 楽器編成 / 声 / 調性・強弱の変化 / 残響・ミックス でほぼ共通の骨格 |

→ Suno が「完成したスタイル」とみなす形のひな形として使える（RP-06）。

注: 当初 `shōtaiko` が `sh?taiko` と記録されていたが、これは Unicode 非対応エディタへの
コピーによる文字化けで、Suno 由来ではない。ただし
**Suno が書き換えたスタイルには `ō` 等の非 ASCII 文字が実際に含まれる**ため、
DP-07（UTF-8 のまま保持）は要件として残る。

### 5-2. インスト先行 → Add Vocal（派生生成の実例）

- 元曲: インスト、3:00
- 操作: リミックス → ボーカルを編集（Add Vocal）
- 生成結果: 2:58〜2:59（**長さは元曲で決まる**）
- 生成曲名: `（元曲名） (Add Vocal)` — Suno が自動付与
- Suno が派生関係を記録している（右パネルに `Instrumental from` 表示）
- 設定値: Weirdness 75% / Style Influence 75% / Audio Influence 75%（いずれも既定値から変更）
- 採用したスタイル: `Japanese Traditional, 和風音頭, 演歌`（英語と日本語が混在）
- Suno 作詞AI の出力形式: 構成タグが英語（`[Verse]`, `[Prechorus]`, `[Chorus]`）、歌詞本文が日本語
- 生成ごとに異なる自動キャプションが付く（例:「female vocals with 演歌風 melodic phrasing」）

含意:

- 派生元のスタイルは**書き換え後**のものであり、**テイクごとに異なる**
  → 派生生成の入力欄では「採用したテイクのスタイル」を貼り付ける必要がある
- 「オーディオの影響」と「スタイルの影響」の配分によって、
  チャットAI が書くべきスタイルの中身が変わる
  - 元音声の影響を強くする → ボーカル関連の記述が中心でよい
  - 弱くする → 曲全体のスタイルを改めて書く必要がある
  - → 派生生成の依頼文には「想定するオーディオの影響の設定」を前提として含める必要がある

### 5-3. 作詞AIへの指示欄の貼り付け挙動（2026-10-17、利用者の観察、1回、ログ・画像あり）

現象:

- 作詞AIへの指示欄に長い文を貼ると、入力欄の本文ではなく、「→ 夜明け前の…」のような**添付チップ**になる
- チップだけでは送信ボタンが押せない。入力欄に一言を入れると送信できる
- 閾値: **240文字まではチップ化せず、241文字でチップ化**（利用者が文字を足して確かめた。貼られた文面で数えた値で、コードポイントと UTF-16 の両方で240。改行なし）
- 276文字（改行を除くと268）の指示文（`rendered-08` 系の指示文）はチップ化した。一言「添付のテーマ・指示に従い歌詞を作成してください」を足して送信し、歌詞が生成された

このときの歌詞の実際（目視。チップ経由の反映度の参考）:

- 作詞AIが構成タグ（`[Verse 1]`・`[Pre-Chorus]`・`[Chorus]`・`[Bridge]`・`[Final Chorus]`）を自分で付けた
- 指示の「夜明け前の駅のホーム」は「白いホーム」「朝の改札」で反映。一方、「短い英語フレーズ」「始発列車」「街灯」は見られず、「友人を見送る」は「君に会いたい」「君のほうへ」という再会に向かう向きになった
- 指示にない Pre-Chorus と Bridge が足され、「最後の短い余韻」は最後のコーラスになった
- 性別を限定しない言い回しは守られていた（一人称なし）

未検証: 閾値が安定しているか（アカウント・画面幅・時期による差）、原因、チップ化した指示としなかった指示で反映度に差があるか、一言の内容による差、チップ側の上限。

含意: 作詞AIへの指示を届けるときの手順に「一言を添える」が加わることがある。`decisions/request-text.md` の B-LY-B は、この観察を踏まえていない（依頼文は変えない）。UI 側での案内は `decisions/ui-and-nonfunctional.md` §3-2・判断ポイント41 に仕様を置いた（2026-10-18。実装は未着手）。参考: `-08` の6モデルが出した指示文の長さは、改行を除いて 176〜495 文字（240文字以内は Namazu 176 のみ）。指示文を240文字以内に収める案（B'）は、`request-text.md` 判断ポイント37 で不採用とした。

## 6. 未採用・記録のみ

- **改善のループ**: v6 は生成結果ごとに自動キャプションを付けるため、
  「キャプションを貼ってチャットAI に改善案を出させる」使い方が考えられる。
  ただし「チャットAI の回答や生成結果を取り込む」機能はスコープ外のため、初版では扱わない
- **作詞家のサンプル歌詞生成**: チャットAI に作詞家作成用のサンプル歌詞を書かせる使い方。
  曲ごとの作業ではなく一度きりの準備作業のため、本ツールの目的とは性質が異なる

## 7. 参考: 第三者情報（対象バージョン v4.5〜v5 期）

現行バージョンでの妥当性は未検証。プリセットや依頼文ルールの参考として記録する。

### スタイルの書き方

- 要素の順序: ジャンル → ボーカル → BPM → 雰囲気
- BPM の目安: バラード 60-80 / ポップス 100-130 / ダンス 120-140
- 複数ジャンルの組み合わせは主ジャンルを先に書き、`with` / `meets` / `inspired by` でつなぐ
- 楽器の役割を明示すると精度が上がる（例: `lead: saxophone, backing: strings and piano`）
- 英語のほうが認識精度が高い

### 日本語歌詞の発音対策

- 読みが複数ある漢字はひらがなで書く
- カタカナ語は英語風に発音されることがある
- 助詞「を」「は」「へ」はローマ字表記で調整できる（多用は不自然）

### 歌詞の分量

- 日本語: 約3分の曲なら200文字以内が理想
- 英語: 3,000文字程度を超えると曲が駆け足になる（v5.5 期）

### その他

- メタタグは確率的なヒントであり、Suno は多くの場合従うが無視することもある
- BPM 指定は目安として扱われ、厳密には固定されない
- v4.5 でプロンプト補助機能が追加された（スタイル欄の魔法の杖アイコンと推定）
- 他人の歌詞を無断で使うのは利用規約違反（Suno 公式ヘルプ）
- プロンプトに著作権のある歌詞や不適切な表現が含まれると生成拒否になることがある
- 公式 FAQ: スタイルタグを完全に制御したい場合はバリエーションを 0（UI 上の「オフ」）にする

## 生成後のスタイル文の観察（2026-09-16）

出典: `../examples/suno-test-01-granularity.md`（H-07 の検証、8曲）

### 除外欄はスタイル文に `-語` として統合される

バリエーション「標準」で生成した際の書き換え後スタイル文は、全て4曲とも末尾が
`‑Celtic, ‑nostalgia, ‑electric guitar, ‑distorted timbres` で終わっていた。

- **「スタイルを除外」欄の内容は、内部的にはスタイル文末尾への `-語` として扱われている**
- 除外語は入力したままの順序・語形で保持され、書き換えの対象になっていない
- 使われている記号は U+2011（non-breaking hyphen）で、通常のハイフンではない

これは `decisions/request-text.md` 判断ポイント（F-03: 除外欄に No や without を付けない）の裏付けになる。
Suno 自身がマイナス記号で否定を表しているため、語に `No` を付けると二重否定になる。

### 書き換えの傾向

入力（基本プロンプト）:
`Orchestral final boss battle theme, Japanese traditional style, tense and majestic, shakuhachi and shinobue lead, wordless choir, taiko drums`

| 観察 | 内容 |
|---|---|
| 先頭要素の残存 | **4曲すべてが `Orchestral` で始まった**。H-01（先頭の要素は書き換えられにくい）の支持材料 |
| 様式名の扱い | `Japanese traditional style` は 4曲中3曲で消え、`shakuhachi` `shinobue` `taiko` などの**具体的な楽器名に吸収された**。音としての和風さは全曲で保たれており、実害はない |
| 追加された要素 | `low strings` `brass` などの伴奏楽器、`wide choral hall reverb` などの空間表現。いずれも入力にないが矛盾もしない |
| 長さ | 短い入力（約140文字）から約250〜300文字に膨らんだ。詳細プロンプト（約600文字）には届かない |

### 曲名の自動設定

- 同じプロンプトの4曲は**すべて同じ曲名**になった（基本: `Final Showdown` / 詳細: `Thundering Final Showdown`）
- 曲名はテイクごとではなく、**入力スタイル単位で決まる**と推定される
  → **2026-09-17 に訂正**: 曲名は**生成リクエスト（1回2曲）単位**で決まり、同じ入力でも生成ごとに変わり得る（H-08 は反証。`../examples/suno-test-02-jp-traditional-vs-style.md` §6-4）
- 今回は入力が英語主体だったため、H-02（曲名の言語が何に依存するか）の切り分けにはならなかった
