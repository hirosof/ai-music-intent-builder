# 依頼文と回答フォーマット

- 最終更新: 2026-09-17
- 対象: Suno / インスト / 新規生成
- 状態: 暫定

前提となる原則: `principles.md`。入力項目: `input-items.md`。
実際の文面: `request-text.md`（ブロック定義）。

---

## 1. 出力フィールドの確定

| Suno の欄 | 出力 | 条件 |
|---|---|---|
| スタイル | **必須** | — |
| スタイルを除外 | 条件付き | 3値選択の「使用しない」または除外の自由記述があるときのみ |
| 曲名 | オプション | 「曲名案を出させる」が有効なときのみ。**末尾に指定数をまとめて**出す |
| 歌詞 | **出力しない** | 空にすることがインストの条件 |
| 推奨パラメータ | オプション | 項目ごとに有効なときのみ |

### 歌詞欄を出力対象から外す理由

依頼文に「歌詞欄は空にせよ」と書くのではなく、**そもそも出力対象から外す**。
「空にせよ」と書くと、チャットAI が空のコードブロックを出したり、
構成タグを書き込んだりする余地が生まれるため。

ただし**インストであることは前提セクションで伝える**。
Q-01（歌詞欄に構成タグのみを入れたときの挙動）が解決したら見直す。

## 2. 出力の粒度（R-17）

これまでの設計では「想定するバリエーションによってチャットAI の書き方を変える」
としていた（R-12）。R-17 はこれを一歩進め、**成果物そのものを複数の粒度で出させる**。

以下は独立した2本の軸として扱う。

- **粒度の軸**: 基本プロンプト / 詳細プロンプト
- **設定の軸**: 想定するバリエーションの値

両方を出させれば、Suno 側で「バリエーションをオフにして詳細プロンプトを使う」
「標準のまま基本プロンプトを使う」といった組み合わせを生成時に選べる。
**依頼文を出し直さずに試行錯誤できる**のが利点。

| 種別 | 内容 | 目安の長さ | 想定する使い方 |
|---|---|---|---|
| 基本プロンプト | 曲の性格を決める核となる要素のみ。ジャンル、様式、情緒の中心、主要な楽器 | 数語〜30語程度 | バリエーションをオフ以外にして、Suno の解釈に任せる |
| 詳細プロンプト | 完成形。テンポ、楽器編成、声、調性や強弱、残響やミックスまで含む | 目標900文字以内 | バリエーションをオフにして、書いたとおりに生成させる |

### 副次的な効果

1. **検証に使える。** 基本プロンプトをバリエーション標準で生成すれば、
   Suno がどう肉付けするかがわかり、詳細プロンプトと見比べられる。
   **実際に H-07 の検証でこの使い方をし、H-01（先頭要素の残存）の支持材料と
   除外欄の内部表現を得た**（2026-09-16）
2. **チャットAI に「何が核か」を明示させる。** 詳細プロンプトだけだと
   重要な要素と装飾的な要素が同じ重みで並びがち。
   RP-06 の「重要な要素を先頭に置く」をより確実に守らせる仕組みになる

### 注意

「両方」にすると1案あたりの出力量が倍近くになる。

検証結果（2026-09-16）: 3案 × 2粒度 × 訳付きでも5モデルすべてが1回の回答に収めた（V-09）。
**現時点で分量の問題はない**。上限の目安を依頼文に書く必要はないと判断する。
項目数や案の数を増やしたときは再確認する。

## 3. 依頼文の構成

| # | セクション | 出す条件 | 内容の出所 |
|---|---|---|---|
| 0 | タイトル | 常時 | 固定 |
| 1 | 依頼の前提 | 常時 | RP-01 ＋ 生成の種類 |
| 2 | 値の状態の読み方 | 常時 | RP-02 |
| 3 | 優先順位 | 常時 | RP-04 |
| 4 | 禁止事項 | 常時 | RP-07 |
| 5 | 対象ツールと出力欄 | 常時 | プロファイル |
| 6 | 楽曲の要件 | 常時 | 入力項目（軸A〜F） |
| 7 | 出力形式 | 常時 | RP-03 / RP-06 / RP-08 / RP-09 / RP-12 |

画像版はルールが各項目のセクションに分散していた。
音楽版では**ルールを冒頭にまとめ、要件はその後に置く**。

セクション5と7の中身はツールと設定によって変わる。
セクション7で条件付きになるのは、曲名案・推奨パラメータ・除外欄の3つ。

### セクション5の書式（プロファイルからの生成）

本ツールの中核。

```
## 5. 対象ツールと出力欄

対象: Suno v6（アドバンスドモード）

### 出力する欄

| 欄 | 上限 | 目標 | 言語 |
|---|---|---|---|
| スタイル | 1000文字 | 900文字以内 | 英語（日本固有のジャンル名・様式名は日本語可） |
| スタイルを除外 | 1000文字 | 900文字以内 | スタイル欄と同じ |

### ツール側で確定している設定（本文に書かないこと）

| 設定 | 値 |
|---|---|
| 長さ | 3:00 |
| バリエーション | 標準 |
| 奇抜さ | 50%（既定値） |

### この設定による書き方の指示

（バリエーションの値に応じたブロック）
```

**「本文に書かないこと」の表を明示的に置く**のが RP-05（指定経路）の実装。
画像版では「解像度はプロンプトに含めない」が文章の中に埋もれていたが、
表にすることで対象を機械的に生成できる。

### セクション6の書式

```
## 6. 楽曲の要件

### A. 用途・文脈
| 項目 | 状態 | 値 | 具体化 |
|---|---|---|---|
| 用途 | 指定 | ゲームのボス戦BGM | 拡張可 |
| 用途の詳細 | お任せ | お任せ — 用途から自然に導ける範囲で | — |
| 想定する聴取環境 | 指定 | ループ再生する | 翻案可 |

（以下、B〜F および除外・補足）
```

**表形式にする理由**: 状態と値が常に対になって現れるため。
散文にすると状態の表記が省略されやすく、RP-02 が形骸化する。

**「具体化」列**は `input-items.md` §1-1 の分類（拡張可 / 翻案可 / 保持）。
状態が「指定」のときのみ値を入れ、それ以外は `—`。

#### 3値選択項目の書式

3値選択を持つ項目（`input-items.md` §1-2）は、使用と除外を列で分ける。

```
### D. 音の構成
| 項目 | 状態 | 使用する | 使用しない | 具体化 |
|---|---|---|---|---|
| 主旋律を担う楽器 | 指定 | 尺八, 篠笛 | エレキギター | 拡張可 |
```

「使用しない」に入った要素は、Suno の**「スタイルを除外」欄に回す**。
グループ7（除外の自由記述）の内容と合わせて、除外欄にまとめて出力する。

## 4. 回答フォーマット

```
## 案 1 / 3

### 基本プロンプト
（コードブロック）

### 詳細プロンプト
（コードブロック）

### 日本語訳
（出力言語がユーザーの母語以外の場合のみ）

### この案の狙い
（1〜2文。何を変えた案かを含む）

### スタイルを除外
（コードブロック。該当時のみ）

---

## 補完一覧
| 項目 | 決めた内容 | 理由 |
|---|---|---|

## 曲名案
（「曲名案を出させる」が有効な場合のみ。
　案ごとではなく、プロンプト全体に対して指定数をまとめて）

## 注意事項
（矛盾の解決、特徴への分解など。なければ省略）
```

### 論点0: 曲名案の置き場所

曲名案は**案ごとではなく末尾にまとめて置く**。
曲名は同じプロンプトから生まれる複数の曲に付けるもので、
プロンプトの案とは独立しているため（R-14）。

### 論点1: 補完一覧は案ごとか、全体で1つか

案1と案2で補完の内容が違うことがあり得る（例: 案1は静かな展開、案2は起伏のある展開）。

| 案 | 評価 |
|---|---|
| 案ごとに置く | 正確だが冗長 |
| 全体で1つ | 簡潔だが案ごとの違いを表せない |
| **折衷（既定）** | 全案に共通する補完を全体の一覧に置き、案ごとに異なる部分は各案の「狙い」に含める |

### 論点2: コードブロックの入れ子

依頼文自体が markdown で、その中に「コードブロックで出力せよ」と指示すると入れ子になる。

対策: **依頼文の中に回答例を含めない。** 形式は文章と表で指示する。
画像版でも回答例は含んでいなかった。

### 論点3: 案ごとの差の付け方

案を複数出させる場合、「何を変えた別案なのか」を指示しないと似たものが並ぶ。
→ 入力項目（グループ9）に「案ごとの差の付け方」を追加した。既定は「お任せ」。

## 5. 判断ポイント（既定値で進行中）

| # | 判断 | 既定値 |
|---|---|---|
| 1 | 歌詞欄を出力対象から外す | 外す |
| 2 | 補完一覧の方式 | 折衷 |
| 3 | 依頼文に回答例を含めるか | 含めない |
| 4 | 案ごとの差の付け方を入力項目に追加 | 追加（既定値「お任せ」） |
| 5 | 出力する粒度の既定 | 両方。Suno 側の使い分けは「詳細＋バリエーションオフ」（H-07 で同等と判定。再現性を優先） |
| 6 | 除外欄の言語 | スタイル欄と同じ（旧: 英語固定）。日本固有の様式を除外する場合に書けなくなるため（`request-text.md` §5） |

## 6. 補完・仮定一覧

| 項目 | 補完内容 | 根拠 |
|---|---|---|
| 目標値 900文字 | 上限 1,000文字の9割 | RP-06 の既定 |
| 基本プロンプトの長さ | 数語〜30語程度 | 実例の入力（`和風戦闘BGM , Choir`）が2要素、Suno の提案チップが短文 |
| 案ごとの差の付け方の選択肢 | 軸C・D・F と「解釈の幅」 | 差を付けるのに適した軸を選定。軸B は変えると別の曲になる |

## 7. 暗黙の前提

- 依頼文は1つのコードブロックとしてコピーする運用を想定（画像版の出力プレビュータブと同じ）
- 回答フォーマットの見出しレベルは、チャットAI の回答が単独の文書として読まれる前提で決めた
- 基本プロンプトと詳細プロンプトは**同じ楽曲要件から生成された2つの表現**であり、
  内容が矛盾しないことを前提とする。
  依頼文に「基本プロンプトは詳細プロンプトの核を抜き出したものである」ことを明示している
  （`request-text.md` B-07-2r。検証では5モデルすべてが守った）
