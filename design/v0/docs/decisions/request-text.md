## 0. 本ドキュメントの位置づけ

DP-04（依頼文はルールブロックの組み合わせで生成する）に従い、
**「完成した1本の文章」ではなく「ブロック定義 ＋ 変数」**として文面を定義する。

理由:

1. セクション5・6・7 の一部は設定によって出し分ける必要があり、1本の文章では条件が表現できない
2. 実装（Claude Code 側）がそのまま参照できる形になる
3. 新規生成／派生生成、インスト／歌あり の追加時に、ブロックを足すだけで済む

変数は `{{ }}` で示す。
**依頼文の中にはコードブロック記号（バッククォート3つ）を一切含めない。**
依頼文全体を1つのコードブロックとしてコピーする運用のため
（`request-format.md` §7 の暗黙の前提）。

## 7. 暗黙の前提

- 依頼文は markdown として**1つのコードブロックでコピーされる**。したがって依頼文内にコードブロック記号を含めない。この制約は §7 の書き方（回答例を出さない）と同じ根に由来する
- チャットAI が markdown の表を正しく読める前提で書いている。表が崩れる環境がある場合、§2・§5・§6 の表は箇条書きへの代替形式が必要になる
- 今回定義したのは **Suno v6 / 新規生成 / インスト** の組み合わせが中心。派生生成は B-03d・B-DF（2026-09-23追加。未検証）を定義済みだが、他のブロック（B-06 の `axes` など）は新規生成と同じ項目集合を使う前提のまま（`song-file.md` §12）。歌ありのブロックは2026-09-28に追加（B-01v・B-04v・B-05g・B-06G・B-LY 系・B-07-9。未検証。仕様側の作業は §8）
- §6 の表は入力項目からの機械生成であり、**選択肢の語彙（プリセット）は未確定**のため、レンダリング例の語は仮のもの
- 「案の数」に既定値が定義されていないため変数として扱った（`input-items.md` グループ9 の既定は「—」）
- チャットAI が §5-2 の「本文に書かないこと」を守る前提。守られたかの検証手段はツール側にない（R-16 の文字数カウンタでも検出できない）
