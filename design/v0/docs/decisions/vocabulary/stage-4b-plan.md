### 1-2. この数字から分かること

- **段階3 で追加した38語をすべて非表示にしても164語で、目安（120）に届かない**。目安に合わせるには、3資料以上に登場する語からも少なくとも44語を非表示にする必要がある
- 3資料以上の語は、細則（V-01〜V-16）で「一般性が高い」とした語であり、数を合わせるために非表示にすると、**規則ではなく数で選ぶことになる**（段階1 の「判断が入らず根拠が追跡できる」という趣旨と衝突する）
- 逆に、段階3 の語を一律に非表示にすると、需要を理由に追加したカテゴリ（日本・東アジア系、シネマティック系。V-12）がほぼ空になる

→ **判断ポイント14 の目安をそのまま適用する前に、目安の意味を見直す必要がある。**

## 2. 論点A: 判断ポイント14 の目安を見直すか

### 2-1. 語数が実際に影響するもの

| 影響先 | 総数の影響 | カテゴリごとの語数の影響 |
|---|---|---|
| 選択 UI（TreeTable。`../presets.md` §4-2） | 小さい。カテゴリ（16）を閉じた状態で表示し、検索もある | **大きい**。カテゴリを開いたときに一度に見る行数 |
| 主ジャンルの選択（単一選択。判断ポイント13） | 同上 | 同上 |
| 「近い系統」の警告ペアリスト（判断ポイント22） | 大きい。語が多いほどペアの候補が増える | — |
| 未検証の語を推奨として見せること（DP-06） | 大きい。表示する語はすべて Suno v6 で未検証 | — |

- TreeTable の方式では、利用者が一度に見るのはカテゴリの一覧と、開いた1カテゴリの語。総数より**カテゴリごとの語数**が操作の負担を決める
- カテゴリごとの語数は、最大がロック系・エレクトロニック系の24で、V-13 の分割の閾値（25）以内
- 目安 80〜120 の根拠は `../presets.md` §6 に記載がない（既定値のみ。議論ログは未確認）

### 2-2. 選択肢

| 案 | 内容 | 利点 | 欠点 |
|---|---|---|---|
| A1 | 目安 80〜120 を維持する | 当初の方針どおり | 3資料以上の語も数で削る必要があり、選び方の根拠が追跡できない |
| **A2（推奨）** | 総数の目安をやめ、カテゴリごとの上限（V-13 の25）だけを残す。**数による非表示は、選択 UI の試作で1カテゴリの行数を実際に見てから決める** | 画面の条件という根拠で数を決められる。非表示は後からいつでもできる（R-19） | 段階4b の一部が実装段階まで持ち越しになる |
| A3 | 新しい総数の目安（例: 150〜200）を置く | 今決めきれる | 新しい数字にも根拠がない |

A2 を推奨する理由: 語数の問題は画面の問題であり、画面ができる前に数字を決めても根拠にならない。非表示は削除ではないため（R-19）、実装段階で決めても保存データは壊れない（将来の修正が容易な仮定）。

## 3. 論点B: 数ではなく規則で非表示にする基準

A2 を採る場合も、画面を待たずに判定できる基準は今適用できる。

### 3-1. 基準の候補

| 基準 | 内容 | 該当する語（見込み） |
|---|---|---|
| **B1 重なり** | 段階4a までに「段階4b で重なりを再確認する」とした組を見直す。一方が他方と他の軸の組み合わせで、対象にない特徴を持ち込まずに表せる場合（V-15 の考え方）は、一方を非表示にする | 判断ポイント70（Drill / UK Drill）、82（Swing / Big Band）、85（Electric Blues / Chicago Blues）、130（Indian Classical / Hindustani Classical / Carnatic Classical）、136（Modern Classical / Contemporary Classical）。0〜6語 |
| B2 根拠の弱い2資料の語 | 段階3 で追加した38語のうち、資料に音の記述がなく一般的な知識だけで判定し、かつ本ツールの用途（ゲームBGM・動画BGM などの例示、Suno の実例）との結び付きがない語を非表示にする | 最大で約34語（38語から、需要を理由にしたカテゴリの雅楽・能楽・民謡・Trailer Music を除いた数）。語ごとの資料の記述の有無は、各ファイルの注記に記録がない語もあり、再確認が必要 |

### 3-2. 推奨

- **B1 は今実施する**。重なりの判定は画面に依存せず、「近い系統」の警告ペアリスト（判断ポイント22）の作成と同じ作業で扱える
- **B2 は今は実施しない**。候補の一覧だけを作る。非表示にするかは、論点A の画面の確認と合わせて決める。理由は次の2つ
  - 38語は V-15 の規則に従って追加しており、非表示にするなら規則の側（V-15 の運用）を見直すことになる
  - 一般的な知識による判定という弱さは、Suno で実際に効くかを確かめないと解消しない（§5 の論点E）

| 案 | 内容 |

## 7. 暗黙の前提

- 選択 UI は `../presets.md` §4 の TreeTable の方式で実装される前提で、カテゴリごとの語数が操作の負担を決めると考えた。平坦な一覧で見せる画面（例: 辞典の全語一覧）では、総数も負担になる
- 利用者は本人のみ（`../scope.md` §0）。表示を利用者が切り替えられる（R-19）ため、既定の表示が多少多くても、自分で非表示にできる

## 8. 手順2 の結果（2026-09-18）

### 8-1. B1: 重なりの組の見直し

基準: 組の一方が、他方と他の軸の組み合わせで、対象にない特徴を持ち込まずに表せる場合は、一方を非表示にする（§3-1）。

| 組 | 判定 | 理由 |
|---|---|---|
| Drill / UK Drill（判断ポイント70） | 両方表示 | どちらも他方の地域のリズムの型を持ち込む。リズムの型を表す軸がない（V-15） |
| Swing / Big Band（判断ポイント82） | 両方表示 | Big Band を「Swing ＋ 編成の規模」で表すと、スウィング期の様式を持ち込む（モダンなビッグバンドと合わない）。Swing を Big Band で表すと大編成を持ち込む（小編成のスウィングと合わない） |
| Electric Blues / Chicago Blues（判断ポイント85） | 両方表示 | Electric Blues を Chicago Blues で表すと、ハーモニカとシカゴのバンドの型を持ち込む。逆は区別の主因（バンドの型）を表せない。なお Electric Blues は組の外の語（Blues ＋ 楽器）では表せ、判断ポイント87 の非対称（Acoustic Blues との差）は残る。B1 の基準の範囲外のため変えない |
| Indian Classical / Hindustani Classical / Carnatic Classical（判断ポイント130） | 3語とも表示 | 総称はどちらの下位の語でも表せない。下位の2語は、総称と楽器の軸では装飾とリズム周期を表せない |
| Modern Classical / Contemporary Classical（判断ポイント136） | 両方表示 | どちらも他方の時代の語法を持ち込む。時代様式は年代の軸で表さない（判断ポイント134） |

**非表示にした語はない。** 既定で表示する語は205語のまま。段階4a で「別物」と判定した組を同じ考え方（V-15）で見直したため、結果は変わらなかった。

上の組のうち、両方を使うと特徴を打ち消し合う組は、警告ペアリストに入れた（`warning-pairs.md`）。
