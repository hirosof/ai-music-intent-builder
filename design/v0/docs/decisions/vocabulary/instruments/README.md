4資料は構成が大きく異なるため、ジャンルの V-09（大分類の資料上の見出し数を数える）を
機械的に適用しにくい。

| 略号 | 資料の性格 |
|---|---|
| C | DTM音源ブラウザ準拠の実用分類（31の番号見出し）。仮想楽器・音色名を多数含む |
| O | ホルンボステル＝ザックス（H-S）を基礎に、アコースティック→民族（地域別）→電子→DTM の順 |
| G | H-S に基づく学術的記述。地域別の民族楽器表、DTM は方式別の比較表が中心 |

### 1-3. 声楽系を採用しない理由（判断ポイント165）

`../../input-items.md` グループ4に「声の扱い」（なし／言葉のない合唱／ハミング等）が
既に独立項目として存在し、値は少数固定（選択式）で、具体化の許容度も「保持」に限定されている。
プリセット式の語彙（多数の選択肢からの選択）を別途持たせる設計上の必要性がない。

### 1-4. DTM製品名・音源方式・ブランド名の扱い（判断ポイント166）

C・O・G・S いずれも、サンプラー製品（Kontakt、Omnisphere 等）、シンセ製品（Serum、Massive 等）、
名機（TR-808、Minimoog 等）を大量に列挙している。これらの大半は**ソフトウェア・ハードウェアの
製品名**であり、Suno のような音楽生成AIが「音として」認識するとは考えにくい
（V-03 (i) 「インストでも音像が成立する」を満たさない可能性）。

一方で、O の資料の Recommendations は「TR-808/909 のような文化的アイコンは固有名詞でも通る」
と述べており、例外の余地を示している。

**方針**: 製品名・ブランド名は原則として語彙の対象外とする。ただし、その製品が代表する
**音色・質感を表す語**（例: `wavetable pad`、`granular texture`、`FM electric piano`、
`808 sub bass`）には変換できる場合があり、これらは通常の語（音色を表す語）として
シンセサイザー系・民族楽器系以外の新カテゴリ（サンプラー・DTM音源ライブラリ系。§1-2 で保留）の
作成時に、段階3 の個別審査（V-03）に準じて扱うかどうかを決める。判定の確定は先送りする。

## 3. 判定の注記

| # | 内容 |
|---|---|
| 1 | 「フリーリード楽器」は C・S が独立した大分類として扱うが、O・G は木管（気鳴楽器）の一区分として扱う。木管楽器系に統合し、段階3 以降で個別に採否を審査する |
| 2 | 「鍵盤楽器」は発音原理上の独立分類ではない（G・S が明記）が、実務上の分類として3資料が独立した大分類を立てているため採用する。ジャンルの `Orchestral`（判断ポイント16）と同型の判断 |
| 3 | 民族楽器系は地域別（日本、中国・東アジア、南アジア、中東、アフリカ、中南米、欧州民俗、オセアニア等）にV-13（25語超で分割）に従い複数カテゴリへ分割する見込み。分割の単位は資料作成時に決める |
| 4 | 同じ楽器が機能別カテゴリ（弦・木管等）と民族楽器系の両方に該当し得る（例: 二胡は弦楽器系にも民族楽器系にも置ける）。ジャンルの多重所属の扱い（`../../presets.md` §1-1）に準じ、複数カテゴリのタグ付けを許容する |
| 5 | 弦楽器系の分割（判断ポイント169。楽器版のV-13相当を前倒しで適用）。全資料が共通して採用する「擦弦・撥弦」の境界で先に2つに分けた。撥弦側（ギター・ベースを含む）は量がさらに多く、作成時にさらに分割する見込み。ジャンルのポップス系作成時と同様、「一度作ってみて量が分かった」パターン（`../README.md` §1-3） |
| 6 | 撥弦楽器系の3分割（判断ポイント171）。楽器の性質（ギター・ベース/ハープ・ツィター/世界のリュート）で分けた。ハープ・ツィターと世界のリュートは共鳴体の形状・地域性がギター・ベースとは異なる。ギター・ベース系は利用者の主要な需要（ポピュラー音楽での使用頻度）が高いため最初に着手した |
| 7 | 打楽器系の3分割（判断ポイント179）。段階1だけで16語に達し、弦楽器系と同様のパターン。Oの「有音程/無音程」の区別と、地域別テーブル（世界の打楽器）の2つの軸で分けた（3つ目の区分としてドラムセット/オーケストラ打楽器を無音程から切り分けた）。音程打楽器系（マレット楽器）は境界が明確で作成しやすいため最初に着手した |
| 8 | 民族楽器系（`world-instrument-family`）を作成しない判断（判断ポイント186）。当初の骨格（判断ポイント164）では「機能別」と「地域別」を別の軸として両方作る想定だったが、実際に各カテゴリを作ると（二胡・尺八・鼓など）民族楽器の大半が自然に機能別カテゴリ（擦弦楽器系・木管楽器系）に入り、さらに撥弦と打楽器は量の問題で地域別のサブカテゴリ（world-lute・percussion-world）を自前で作った。結果として「world」の受け皿はすでに存在し、独立カテゴリを作ると同じ楽器を別名で二重に載せるだけになる |

## 4. 補完・仮定一覧

| # | 内容 | 根拠 |

| 1 | 「大分類の採否」をV-09/V-10に準じて3資料以上を基準に判定した | ジャンルの選定細則をそのまま流用するのが最も再現可能 |
| 2 | カテゴリの id 命名を `-instrument-family` とした | ジャンルの `-family` と衝突しないようにするため（保存データ上の `id` は一意である必要がある。`../../presets.md` §1-3） |
| 3 | 声楽系を不採用としたが、将来「声」のプリセット式語彙が必要になった場合はこの判断を見直す余地がある | 現時点の入力項目の設計（少数固定選択）に基づく判断のため |

## 5. 暗黙の前提

- 楽器の語数はジャンルより多くなる可能性が高い（4資料とも数百の楽器名を列挙している）。V-13（1カテゴリ25語）の分割は、ジャンルより頻繁に発生する見込み
- DTM製品名・音源方式の扱い（判断ポイント166）が確定しないと、シンセサイザー系・民族楽器系以外の新カテゴリ（サンプラー・DTM音源ライブラリ系）の作成には進めない
- 「主旋律を担う楽器」「伴奏・支える楽器」「リズムの担い手」の3項目でこの語彙を共有する前提（`../../input-items.md` グループ4）に立っているが、項目ごとに語彙を絞るべきか（例: 金管楽器は伴奏には出すがリズムの担い手には出さない）は本ドキュメントでは未検討
