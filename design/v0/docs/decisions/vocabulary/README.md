## 1. 選定の方針と手順

### 1-1. 資料をそのまま使えない理由

**資料には軸が混ざっている。**
例えば ChatGPT の資料には `Boss Battle` `Town Theme` が**ジャンルとして**並んでいるが、
本ツールでは軸A（用途）であってジャンルではない。

| 資料上の記載 | 本ツールでの行き先 |
|---|---|
| Cinematic, Epic Orchestral, Synthwave | 軸B ジャンル |
| Boss Battle, Town Theme, Ending Theme | 軸A 用途 |
| Dark, Epic, Dramatic | 軸C 情緒 |
| Japanese Traditional, Celtic, Balkan | 軸B 地域・文化の様式 |
| Orchestral, A Cappella, Big Band | 軸B（判断ポイント16） |

振り分けが先に必要。ただしこれは無駄ではなく、
**用途と情緒のプリセットを作るときの材料にもなる**。

**「Suno が認識するか」は別問題。**
`../principles.md` DP-06 の優先順位でいうと、これらは「バージョン明記のない第三者情報」にあたる。
AI が知っているジャンル名と、Suno が音として区別できるジャンル名は一致しない。

### 1-2. 選定の手順

| 段階 | 内容 | なぜこの順か |
|---|---|---|
| 1 | **3資料以上に登場する語を抽出** | 判断が入らず根拠が追跡できる。一般性の高い語が自動的に浮かぶ |
| 2 | **Suno での実績がある語を追加** | 段階1で落ちても Synthwave・City Pop などは残す。`../../research/suno-profile.md` の実例と突き合わせる |
| 3 | **本ツールの用途から必要な語を追加** | ゲームBGM やカバー画像連携（R-18）を想定しているので Cinematic 系は厚めに |
| 4a | **規則による刈り込み**（カテゴリごと） | §2 の V-05。数と無関係に判定できるため、カテゴリ作成時に行う |
| 4b | **数を見て既定で非表示にする** | 多すぎると選べない。規則で判定できる重なりの見直しは全カテゴリ完了後に行い、数による非表示は選択 UI の試作でカテゴリごとの行数を見てから決める（判断ポイント154・155。`stage-4b-plan.md`）。削除はせず、辞典に残す（`../presets.md` §11） |

### 1-3. 進める単位

**カテゴリ単位で進める**（ポップス系 → ロック系 → …）。
一度に全体を処理すると `term` の要否判断が雑になる。
また最初の1カテゴリで、カテゴリ設計と命名規則（「〜系」、`../presets.md` §3-2）の検証も同時にできる。

楽器はジャンルより分類が明確（弦・木管・金管・打・鍵盤・電子・民族）なので、
ジャンルの方式が固まってからのほうが早い。

ただし、ポップス系を作成した結果、**カテゴリの一覧が先に要る**ことがわかった。
境界の判断（Power Pop のロック系タグ、Latin Pop のラテン系タグ、演歌・トロットの行き先）は
隣のカテゴリの有無で結論が変わり、V-02 は採用済みのカテゴリにしか適用できないため。
2カテゴリ目以降の前にカテゴリの骨格を決めた（§3）。

## 2. 選定の細則（V-xx）

| V-14 | 語の配置（V-02 の入力）の決め方。(1) 語の配置は、その語が属する見出しの経路（大分類から小見出しまで）を §3-5 の対応表でカテゴリに読み替えたものをすべて合わせたもの。(2) 小見出しになっている語（O の J-POP など）は、その見出しを子の語の判定にだけ使い、自身の判定には使わない。最上位の見出しと同名の語（代表項目。例: Rock）には使う。(3) 「A／B」のように複数の系統を名指しする見出しは各カテゴリに対応付ける。名指しせずに複数カテゴリにまたがる見出しと、V-11 の見出しは対応付けない。(4) 1資料内で複数箇所に出る語は、全箇所の対応先を合わせて1回と数える。(5) 1つの語の審査（段階1〜4a）は1回だけ行い、所属カテゴリのうち先に作成するカテゴリで実施して記録する。審査に別カテゴリの論点が必要な場合は、そのカテゴリの作成時に送ってよい。過半数に達しない語は、判断で審査先を決めて記録する。(6) 最上位の見出し名は、代表項目の候補としてのみ数える。複数の系統を1カテゴリにまとめた場合（V-10 の併記、判断ポイント28・29 など）、代表項目に選ばなかった名称は語として数えず、カテゴリの検索用の別名にする（`../presets.md` §11-4）。ただし、一覧の語や本文中のジャンル名としても現れている場合は通常どおり数える。(7) 本文中の言及のうち、他のジャンルとの関係（由来、融合の素材、影響）を説明するために名前を挙げたもの（例: G の「ディープハウスにジャズの和声…を融合させた Amapiano」の Deep House と Jazz）は、V-01 の出現には数えるが、配置には数えない。配置に数えるのは、見出し・一覧・表の行の語と、その節の系統の一員としてその語自体を説明・列挙する本文の言及（例: S の「サザンヒップホップ — 南部。クランク、バウンスなど」の Crunk） | V-02 の「系統」を資料の見出しから機械的に求めるため。(2) の後段は、ロック系の適用時に「Rock は O/G/S では最上位の見出しにしか現れず、自己参照を禁じると代表項目の所属が決まらない」と判明して補った。(5) は同じ語を複数カテゴリで重複審査しないため。(6) は、エレクトロニック系で Dance（4資料とも見出しにしか現れない）を語として数えた誤りから補った。(7) は、ジャズ系で Jazz が他のジャンルの由来としての言及だけでワールド系 3/4 になったことから補った。V-02 の「資料がその系統に置いた」という趣旨に合わせる（判断ポイント80） |
| V-15 | 段階3 (ii) の「代替できる」の定義。代替に使うジャンル語が、対象の語にない顕著な特徴（テンポ帯、展開の型、編成、地域性など）を持つ場合は、代替とみなさない。その特徴を他の軸で打ち消す必要がある組み合わせ（例: 速さが特徴の語 ＋ 遅いテンポ感）も同様。他の軸で特徴を**付け加える**部分はこの制限を受けない。旋律の性格・和声・リズムの型・奏法を表す軸はないため、これらが区別の主因である語は他の軸では代替できない | (ii) の読み方が「組み合わせで音像を記述できれば代替」（Speed Metal など）と「持ち込む特徴がなければ代替」（Melodic Death Metal）で混在していた。Melodic Techno の指摘で判明し（2026-09-17）、既存カテゴリの段階3 を再判定した |
| V-16 | 語の記録の規則（R-19）。段階3・4a・4b で追加しない／除外とした語は、審査したカテゴリのファイルの JSON に `defaultVisible: false` と `exclusion` を付けて記録する（形式は `../presets.md` §11-2）。`categories` には審査したカテゴリを入れる。ラベル・`id`・別名は既定で表示する語と同じ規則（V-06・V-08・判断ポイント21・39）に従う。次は記録しない: 語ごとの判定がない語（「1資料のみの語 ほか」のまとめ行）、他カテゴリへ送った語（送り先で記録する）、V-14 (6) で語として数えない名称 | 除外した語も利用者が表示して使えるようにするため。語ごとの判断をしている作成時に記録するのが最も安い |
