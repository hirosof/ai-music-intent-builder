## 2. 確認した事実（2026-09-19 時点。ライセンスの解釈は最終的に利用者が確認する）

- PrimeTek が「PrimeUI」というライセンス体系を発表（2026年6〜7月）。対象は今後の新メジャー版（PrimeVue 5 など）で、オープンソースとしては配布されなくなる。出典: `https://primeui.dev/nextchapter`

- Community ライセンスは、個人・学生・非営利・小規模組織（年商1億ドル未満、開発者5人未満など）に無料。12か月ごとに更新が必要で、キーが無効になるとライセンス通知が表示されることがある。商用は1開発者あたり $599（2026年末まで）、2027年から $799
- コミュニティフォークとして OpenVue（PrimeVue 4.5.5 の MIT 継続）がある。ベータ。PrimeTek とは無関係の新しいプロジェクトで、継続性は未知

## 4. 候補ライブラリの確認（D案）

要件は `presets.md` §4-2・§4-3。利用者の判断（2026-09-19）: **キーボード操作は必須ではない**。1列目のアイテムのクリックでサブ項目が展開するのは、あったほうがよい。

| 候補 | ライセンス・保守 | 階層 | 各行に3値ボタン | 備考 |
|---|---|---|---|---|
| Element Plus | MIT。最新 2.14.x、活発 | 階層データのテーブル（`row-key`＋`children`） | 列のテンプレート | 1列目クリックの展開は `toggleRowExpansion` を結線 |
| Nuxt UI | MIT。Nuxt なしの Vue＋Vite で動く（Tailwind CSS が前提） | Table の tree data（`get-sub-rows`。公式に例がある）、Tree | Table のセルのスロット | 検索は TanStack Table のグローバルフィルタ（`filterFromLeafRows` で、子が一致すれば親を残す）。別名は検索用の列で解決（利用者の提案）。Tree の基盤（Reka UI）は Alpha |
| Vuetify | MIT（今回は未確認） | **`v-data-table` のグループ化**（利用者の指摘）、Treeview | セルのスロット | 検索は `search` と `custom-filter` |
| Ant Design Vue | MIT。最新は約1〜2年前の 4.2.6 で、更新が止まっている | Table の階層データ | セルのスロット | 優先度は下げた |

**訂正**: 当初、Vuetify のデータテーブルには階層行がないとして「×」とした。これは誤りで、グループ化によって、カテゴリ → 語の2段（`presets.md` §9 の「2段まで」）を実現できる（利用者の指摘）。

**訂正（2）**: Nuxt UI の検索を「自前」（△）として、階層表示の検索ができないような書き方をしていた。これも実際は、公式ドキュメントの Table に「With tree data」と「With global filter」の例が別々にあり、組み合わせた例がないだけだった（利用者の指摘）。TanStack Table のグローバルフィルタは階層データに対応し（`filterFromLeafRows`）、Nuxt UI の Table はこれを `global-filter-options` で渡せる。試作で、組み合わせて動くことを確認した（§5）。

- 検索（要件3）は、語彙が約630語でメモリ上にあるため、どのライブラリでも階層データを絞り込む関数を書けば同じ動作になる。決め手にならない
- キーボード操作が必須でなくなり、Nuxt UI の強みが決め手でなくなった

## 5. 試作（Element Plus、Vuetify、Nuxt UI）

利用者の了承（Element Plus を第一候補に、試作で確かめる）を受け、Vuetify も同じデータ・同じテストで並べた。Nuxt UI は、上の訂正（2）を受けて追加した。成果物は `tree-select-prototype.zip`（`prototypes/tree-select/` に置く想定）。

- 実データ（`genre.json`）で、階層の開閉、1列目クリックでの展開、別名を含む検索と自動展開、3値の切り替えと同じ語の別カテゴリへの反映、`itemOrder` の並び、非表示の語の表示を検証（jsdom）
- 3つとも、49テスト（共通ロジック11、Element Plus 12、Vuetify 11、Nuxt UI 15）が通る。型検査とビルドも通る
- **Nuxt UI**: `get-sub-rows` で階層データを表示し、`global-filter` に `filterFromLeafRows: true` を渡して階層を保った検索ができた。**別名は、「検索用」の非表示の列（正規化した名前・別名・英語表記・所属カテゴリ名）を設けて解決**した（利用者の提案）。非表示の列もグローバルフィルタの対象になる。検索中は `expanded` に、残ったカテゴリの key だけの Record を渡して開く（`true` だと葉の行にも空の展開行が作られる）。ひらがなでも、カテゴリ名でも見つかる。閉じた子行は DOM に出ない。前提として Tailwind CSS 4 が要る
- 分かったこと: Element Plus は、閉じた子行も DOM に置き `display:none` で隠す（初期230行）。Vuetify は同じ語をカテゴリの数だけ行にする必要がある（グループ化は1行が1グループにしか属せないため）。Vuetify は組み込みの検索に載せられる
- ライブラリに依存しない部分（データ加工・検索・選択状態）は `shared/` に分けた。ライブラリを替えても作り直さない
- ビルドの参考値: Element Plus は JS 902KB（gzip 285KB）＋CSS 361KB、Vuetify は JS 659KB（gzip 209KB）＋CSS 500KB（この2つは全部入り）、Nuxt UI は JS 338KB（gzip 100KB）＋CSS 197KB（使う部品だけ）。公平な比較ではない。実際は前2者もオンデマンドの読み込みで小さくなる

**未検証（目視が必要）**: 見た目、実ブラウザでの操作感・性能、スマホ幅、アクセシビリティ。

**目視で見つかった不具合（Nuxt UI 版、利用者のスクリーンショットと指摘。修正済み）**: ①各行の間に空の行が入る ②名前列の「>」が名前と別の行になる。どちらも Nuxt UI の制約ではなく、試作の実装の問題だった。①は、`UTable` が展開した行の直後に展開用の空の行を足すのに、`expanded` を `true`（すべて展開）にして葉の行にも作らせたことと、公式の tree data の例の `ui` の指定を入れ忘れたことが原因。②はアイコンがブロック要素として描画されたことが原因。展開をカテゴリの key だけの Record にし、公式の `ui` を入れ、名前のセルを `flex` にして直した。jsdom のテストは DOM の構造しか見ないため、この種の見た目の不具合は検出できなかった（目視が必要とした理由）。他の2つの目視の結果も、同じく必要。

**目視で見つかった不具合（2）（Element Plus と Vuetify、利用者の指摘。修正済み）**: 「非表示の語も表示」を切り替えると、開閉の状態がリセットされる。切り替えのたびに開閉の状態を初期化していたのが原因（Nuxt UI 版は元から保たれていた）。開閉の状態を保つ形に直し、あわせて「検索を消すと検索前の状態に戻る」を3つで同じ挙動にそろえた（こちらはこちらからの追加で、不要なら外せる）。Element Plus は、表の `expand-change` で組み込みの矢印での開閉も追う。テストを修正前に足して不具合を再現してから直した。
