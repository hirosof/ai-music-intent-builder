# 利用者の目での動作確認のチェックシート（ひな形）

- 作成: 2026-11-03（引き継ぎ書の追記54、宿題62）
- 中身の出どころ: 仕様（`decisions/`・`specifications/`）と実装の記録（`implementation-guide.md` §6）

## 使い方

**このファイルには書き込まない。確かめるときは、リポジトリ直下の `temp/`（git の管理外）に写して、写しにチェックを付ける。結果は残さない。**

写す方法: リポジトリ直下の `copy_user-check.bat` を実行する（`temp\user-check\` に日時つきの名前で写す。前の写しは残る）。

代わりの方法（写し先は `temp\` の下ならどこでもよい）: エクスプローラーでコピーするか、コマンドプロンプトで、リポジトリ直下で次を実行する。

```
copy design\v0\docs\checklists\user-check.md temp\user-check.md
```

写しは `temp\` に溜まるが、`temp\` は git の管理外のローカルの一時フォルダで、要らなくなったら利用者が消す。

- ひな形にチェックを付けてしまうと、`tools/check-docs/check_docs.py` がエラーにする（A6）
- 使う節を選ぶ: デプロイのたびに A。機能を変えたら、その機能の B。スマホの作りを変えたら C
- 公開先の URL は、リポジトリ直下の `README.md` にある。localStorage は公開先ごとに分かれる（UI 72）
- **注意が「仮のデータで確かめる」の項目**は、データを消す・置き換える。シークレットウィンドウか、ふだん使っていないブラウザで開いて確かめる（保存先が分かれるので、ふだんのデータに触れない）。ふだんのブラウザで行うときは、先に、プロファイル管理の「すべて書き出す」で控えを取り、編集中の内容も「書き出す」で控える

### 結果の書き方

各項目の「チェック結果」の OK か NG にチェックを付ける。

- どちらにもチェックがなければ、未確認
- OK は問題なし、NG は問題あり
- コメントがあれば、「OK：…」「NG：…」のように続けて書く
- 両方にチェックがあれば、NG とみなす（付け間違いなら直す）
- NG の項目は、その行を貼って設計スレッドの議題にする

## 項目の書式

全項目で同じ形にする（ほかの形式へ変換しやすくするため）。新しい項目もこの形で書く。形は `tools/check-docs/check_docs.py` が確かめる（A7）。

```
- **A-01** 公開先が開き、一覧と依頼文が出る
  - 端末: PC
  - 手順: 公開先の URL を開く
  - 期待: …
  - 関係: UI 1・UI 55
  - チェック結果
    - [ ] OK
    - [ ] NG
```

| 欄 | 内容 |
|---|---|
| 先頭の行 | 番号（節の記号と連番）、確かめること |
| 端末 | PC／スマホ／両方 |
| 手順 | 操作の順序 |
| 期待 | 期待する結果 |
| 関係 | 関係する判断ポイント。系統と番号で書く（UI・入力項目・語彙・文面・ツール。`implementation-guide.md` §8） |
| 注意 | データを消す・置き換える操作のときだけ。文言は「仮のデータで確かめる」。「関係」と「チェック結果」の間に置く |
| チェック結果 | 子の項目として OK と NG。ひな形ではどちらも空 |
