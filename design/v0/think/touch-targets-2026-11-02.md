# 押せる要素の大きさの洗い出し（宿題60 の第1段階。2026-11-02）

調べただけで、コードは変えていない（判断ポイント77 の実装のあとの状態を調べた）。どの値・どの案にするかは設計スレッドが決める。推奨は §6 に書く。

## 1. 要点

- **目安より小さいものが大半。** 実測で高さ 40px 以上の押せる要素は、複数行の入力欄（52〜72px）だけ。最も多いのは 24px（`size="xs"`）、チェックボックスとラジオの四角は 16×16px。
- **`size="xs"` は 12ファイル28か所**（判断ポイント77 の前は35か所。行の操作の7か所がメニューに変わった）。
- **影響が最も大きいのは階層テーブル。** 全部開いたジャンルの表（語の行396＋カテゴリの行16＝412行。複数のカテゴリに入る語は行が複数になる）は 17,811px から、40px で 26,275px（1.48倍）、44px で 28,107px（1.58倍）になる。表の枠の中に見える行は約12行から約8行に減る。
- **画面の横のはみ出しは、40px・44px とも起きなかった**（375px で `scrollWidth` は 375 のまま）。折り返しが増えるのは、複数選択の帯（1行 → 2行）と、長い名前の行だけ。
- **大きさ以外で目立つ問題が2つある。** 楽器の表は 375px で幅 611px（枠 341px）あり、操作の列の多くが横にスクロールしないと見えない。セクションの行では「下へ」の隣に、確認なしで消える「削除」がある。
- **`pointer: coarse` で分ける方法は、測定の環境（スマホの模擬）で働いた。** 実機では確かめていない。

## 2. 調べ方

- 開発サーバを 375×812 のスマホの模擬（`pointer: coarse` が真）で開き、`getBoundingClientRect` で測った。値は px、**高さ×幅**。
- 「隣」は、ほかの押せる要素までの最短の距離（一度に測れた範囲）。0 は接している。
- 「代替」は、同じ動きを別の押し方でできるか。
- 40px・44px の影響は、最小の高さと幅を与える一時的な CSS をページに差し込んで測った（§5。コードは変えていない）。計算で出した値には「計算」と書く。
- データは測定用の仮のもの。終わったあとブラウザのデータは元に戻した。

## 5. 40px と 44px の影響（375px で実測）

一時的な CSS で、ボタン・選択欄・入力欄・タブ・チェックボックス・ラジオ・カテゴリの領域・ハンドルに最小の高さ（ボタンなどは幅も）を与えて測った。

| 場所 | 今 | 40px | 44px |
|---|---|---|---|
| 語の行の高さ | 37 | 53 | 57 |
| カテゴリの行の高さ | 33 | 53 | 57 |
| ジャンルの表（非表示も表示、全部開く。412行） | 17,811 | 26,275（1.48倍） | 28,107（1.58倍） |
| サブジャンルの表（全部開く。230行） | 8,445 | 12,189（1.44倍） | 13,109（1.55倍） |
| 楽器の表（138行） | 5,057 | 7,313（1.45倍） | 7,865（1.56倍） |
| 表の枠（447px）に見える行 | 約12 | 約8 | 約8 |
| サブジャンルの表の幅（枠 341） | 445 | 457 | 461 |
| 楽器の表の幅（枠 341） | 611 | 611 | 615 |
| 雰囲気の行（12行） | 37 | 53 | 57 |
| セクションの行（2行のまま） | 60 | 88 | 96 |
| 構造のカードの中身の高さ | 648 | 728 | 758 |
| 長さの候補 | 1行 | 1行 | 1行 |
| プロファイルの行（名前が1行、フォルダ） | 41 | 57 | 61 |
| プロファイルの行（更新日時あり） | 57 | 57 | 61 |
| プロファイルの行（長い名前） | 104 | 128 | 128 |
| 複数選択の帯 | 41（1行） | 105（2行） | 113（2行） |
| カードの見出し | 28 | 40 | 44 |
| 辞典の表（396行。計算） | 36,228 | 約36,490（+0.7%） | 約36,880（+1.8%） |
| 画面の `scrollWidth` | 375 | 375 | 375 |

読み方の注意:

- **表の行の増え方は、セルの余白を詰めると減らせる。** 行の高さは「ボタン＋余白 12＋罫線 1」。指の端末で上下の余白を 0 にすれば、語の行は 41／45px になる。このときサブジャンルの表（230行）は約 9,430／10,350px（1.12倍／1.23倍。計算）。
- **長い名前の行とチェックボックスまわりは、やや多めに出ている。** 測定では四角そのものを広げたので、名前の幅が減って折り返した。押せる領域だけを広げる方法なら起きない。
- **辞典の表の値は計算。** スイッチの外側の高さが固定で、測定の CSS が行に効かなかったので、行の高さを「今の高さと、目安＋13 の大きいほう」として計算した。この表は説明の文の折り返しで行がすでに高い（中央値 73px）ので、影響は小さい。
- **40px と 44px の差は小さい。** 階層テーブルで1割弱。折り返しの増える場所は同じ。

## 6. 実装の方法の案と推奨

| 方法 | 利点 | 注意点 |
|---|---|---|
| Nuxt UI の `size` を切り替える（`useMediaQuery('(pointer: coarse)')` で） | 文字と余白も含めて整う | 使っている箇所をすべて書き換える。JavaScript の判定になる。44px に当たる `size` は標準にない（`xs` 24、`sm` 28、`md` 32 は実測。`lg`・`xl` は未測定） |
| `main.css` に `@media (pointer: coarse)` で最小の高さ・幅を与える | 1か所で済み、PC に影響しない | Nuxt UI の内部の印（`data-slot` など）に依存する。版を上げると確認が要る。例外の指定が要る |
| Nuxt UI のテーマの上書き（`vite.config.ts` の `ui()` に、Tailwind の `pointer-coarse:` を渡す） | 公式の設定の経路で、部品ごとに書ける | 部品ごとに書く。今は未使用の経路。`tailwindcss` に `pointer-coarse` の記述があることだけ確認し、動作は未確認 |
| 押せる領域だけを疑似要素（`::after`）で広げる | 配置が変わらない。チェックボックスやスイッチの見た目を保てる | 親の `overflow` で切れる。隣との間隔が狭いと領域が重なり、押し間違いの原因になる |

共通の注意:

- **jsdom ではメディアクエリを評価できない。** 単体テストで大きさを確かめられない。今は e2e も使っていないので、画面の測定か実機の確認に頼ることになる。
- **`pointer: coarse` は主な入力だけを見る。** タッチ画面つきの PC（主はマウス）では大きくならない。タブレットにマウスをつないだときの動きは未確認。

推奨（判断は設計スレッド）:

1. 目安は設計スレッドの案どおり 44px が妥当。40px との差が小さく、余白を詰めれば表の増え方も抑えられる。
2. セクションの行と複数選択の帯は (b) メニューを先に検討する。(a) だと最も形が変わる2か所で、ここに判断ポイント77 と同じ理由が当てはまる。
3. 階層テーブルは、カテゴリを (c)、3択と「選ぶ」を (a) にし、指の端末でセルの上下の余白を詰める。
4. 実装は `main.css` の `@media (pointer: coarse)` を基本にする。チェックボックス・ラジオ・スイッチは押せる領域を疑似要素で広げる。箇所が多く、PC の見た目を確実に保てるため。

## 7. ほかの押しにくさ

1. **楽器の表の横スクロール。** 375px で表の幅が 611px、枠が 341px。名前の列だけで 331px あり、操作の4列のほとんどが最初は見えない。大きさの変更とは別の問題で、列の順や名前の列の幅の見直しが効く。サブジャンルの表も 445px で、「—」が見切れる。
2. **セクションの「削除」が確認なしで、「下へ」の隣にある。** 間隔は 4〜8px。元に戻す操作もない。
3. **反対の意味のボタンが接している。** 「使用する」「使用しない」は間隔 0。「—」は幅 28px しかない。
4. **カテゴリの開閉で、押せない所がある。** 行は 33px だが、押せるのは内側の 20px だけ。
5. **語の別名・英語の表記が `UTooltip` の中にある。** 指の端末で出せるかは未確認。検索で別名が当たるのに、なぜ当たったかが見えない可能性がある。
6. **表の中のスクロールとドロワーのスクロールが入れ子。** 表の枠は高さ 55vh で、その外側もスクロールする。指で動かしたときの感触は未確認で、行が高くなると表の中を動かす量が増える。
7. **ハンドルを大きくすると、スクロールできない領域も広がる。** ハンドルは `touch-none`（判断ポイント76）。
8. **フォルダの名前は文字の幅しか押せない。** 短い名前（24×48）では、すぐ右を押すと選択が切り替わる。害は小さい。
9. **一括選択の四角と ▼ が小さいまま隣り合う。** 16×16 と 24×24 で、間隔 8px。

### 9-4. 実測で見つけて直したもの

1. **チェックボックスとラジオの押せる範囲が切れていた。** `::after` の計算値は 44×44 だが、部品の `overflow-hidden` で切れ、四角の外は押せなかった。計算値の確認では見つからず、`elementsFromPoint` で分かった。`overflow: visible` にし、角の丸めを中身に引き継いだ。
2. **フォルダの選択の行が 28px のままだった。** `role="radio"` の素のボタンで、Nuxt UI の四角を除く指定に巻き込まれていた。除く指定を `data-slot='base'` のものだけに絞った。
